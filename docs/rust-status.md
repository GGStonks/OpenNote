# Rust port: where it stands

The plan is docs/rust-rewrite-roadmap.md. The port is developed on the `opennote-rs` branch
(origin `GGStonks/OpenNote`, branch `opennote-rs`). The app does not use any of it yet: what ships
is the TypeScript app in `src/`.

`npm run test:rust` (`cargo test --workspace`) runs every crate's tests. The ones that read
`bench/recordings` (nib's golden test does not) need the recordings, which are not in git.

| Crate | Ports | Checked against the TypeScript app | Not yet |
|---|---|---|---|
| `nib` | the ink engine (`src/ink/engine`) | **exactly**: `bench/engine-golden.json` to 1e-4 px (finished line, `nibStroke`), live line hash for hash on every sample (asserts 0 mismatches) | — |
| `model` | note types, packed points, sheets, migration, the `.opennote` codec | **both ways with the app's own files**: `npm run test:storage` writes a backup and an `.opennote` of every recording (314 strokes, 44,023 points); `crates/model/tests/ts_roundtrip.rs` reads them exactly and writes its own, which the TypeScript side reads back point for point | reading the app's IndexedDB data (roadmap Phase 6) |
| `ink` | densify, widths, smoothing, dashes, geometry, live stroke, precision eraser, overshoot fixes | **point for point** on 36 recorded strokes (`crates/ink/tests/reference.rs` against `npm run bench:rustref -- bench/rust-ref/ink.json`): engine points, modelled line, widths, drawn line (`strokeGeometry`, 2.9.4's smoothing), live line, dash runs, and precision eraser to 1e-4 px; four overshoot mechanisms (`crates/ink/tests/overshoot_fixes.rs`): prediction purge on UP (`StrokePredictor`), real-time liftoff jitter pressure gate (< 0.05) and instant lead drop, quadratic Bézier spline endpoint termination without straight pieces, critically damped spring (`CriticallyDampedSpring`), rs.10 tail-erasure fix, rs.11 input layer alignment, and rs.12 nib modeler optimizations (has_force flag, attack_force caching, singular poly_fit0 fallbacks), index-based thinning in thinned_widths, SmoothLiveStroke boundary width continuity, fast-chord turn clamping, and closed stroke eraser seam merging; benches match 2.9.4-rs.12 baseline | — |
| `shapes` | shape recognition, the smart pen (hold to snap, all tools), shape handles, selection, z-order | **against `npm run bench:rustref`** to 1e-4 px: recognition on 352 recorded and synthetic strokes (`tests/reference.rs`), the smart pen on 346 recordings for pen, highlighter, eraser, lasso and the Draw tool's curve (`tests/smart_pen_reference.rs`), 458 rect and lasso selections, bounds, transforms, z-order and shape-edit handles (`tests/selection_reference.rs`) | — |

| `svg` | SVG export (`svgExport.ts`) | **against `npm run bench:rustref`**: `layerSvg` / `svgHead` on 191 strokes (the recordings in every line style, highlighters, a fill, an arrow), same elements and attributes, numbers to 1e-4 (`tests/reference.rs`); text and image blocks by unit tests | rich text and formulas as foreignObjects (the TypeScript export needs a DOM) |

| `canvas` | the page on the GPU (wgpu: Metal on iOS, Vulkan / GLES on Android), the passes of the page's WebGL ink (`glInk.ts`): coverage runs, even-odd fills, holes, hatches, arrows, paper patterns in WGSL; vector engine architecture, spatial index (R-Tree), infinite zoom SDF primitives, and cross-platform zero-copy FFI bridge; docs/rust-native-canvas.md N1-N2 | the CPU renderer (`crates/canvas/tests/compare.rs`), GPU canvas (`npm run bench:canvas`), and vector canvas test suite (`crates/canvas/tests/vector_canvas_tests.rs`): double-precision ViewMatrix stability, R-Tree spatial indexing, vector eraser (object & precision split), lasso marching-ants selection on_pointer_up with exclusive outside-tap dismiss, hold-to-shape (~350ms) & magnetic angle snap, and C ABI engine lifecycle; builds for aarch64-apple-ios and aarch64-linux-android | device surface integration in shells (N2), pictures, PDF pages, blocks (N4, N5) |
| `native` | the app's entry point on the devices (iOS static library, Android JNI): `geometry` (the drawn lines of strokes), the live line while writing (`live.rs`, the shells' `r`), `renderThumbnail` (Phase 2 renderer bridge), `canvasRender` and `CanvasHost` FFI, selection & transformation bridge (`selectInRect`, `selectInLasso`, `selectionBounds`, `transformPageItems`, `shapeHandles`, `moveShapeHandle`, `snapStroke`), and `opennote_canvas_engine_*` zero-copy input FFI | the page's own lines through it: `bench:ui --only rustcore` (Rust check, 3,031 strokes, 0 differ), `crates/native/tests/geometry.rs` (every reference kind through the framing), `tests/live.rs` (57 live lines of the reference), `tests/render.rs` (thumbnail, GPU canvasRender, selection and CanvasHost FFI lifecycle), `bench:ui --native --only rustlive` (the shell's Rust line = the page's `u` line), `tests/jni/run.sh`; benches match 2.9.4-rs.18 baseline | a run on the devices |

Spikes present in `spikes/`:
- Spike A (`spike_a_ink`): 240 Hz coalesced touch ingestion buffer and 120 Hz render pipeline.
- Spike B (`spike_b_text`): Rich-text layout via `parley 0.12.0`.
- Spike C (`spike_c_formulas`): `mitex 0.2.4` math layout.
- Spike D (`spike_d_pdf`): `hayro 0.9.0` PDF rendering.
- Spike E (`spike_e_tikz`): `wasmi 2.0.0` running `tex.wasm`.
- Spike F (`spike_f_ui`): UI evaluation matrix.
